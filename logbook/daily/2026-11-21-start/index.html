    logical-minds-foundry: no failed runs in its private repos.

    Automation PRs. None merged in the window. Four are open, and all four are stuck on failing checks:

    • vergil-project/vergil-containers#980, "chore(upstream): refresh upstream inputs", 3 hours old: a security-related failure, vergil-project/.github#1473.
    • logical-minds-foundry/mq-resiliency-lab-for-linux#1746, "chore(repo-config): sync the managed files with the released templates", 5 hours old: the docs build (logical-minds-foundry/mq-resiliency-lab-for-linux#1738) and a security-related failure (logical-minds-foundry/.github#413).

    Each sync PR is closed and opened again every night, so its age resets; the failures behind them are older than the PRs show.

    Releases. No releases in the window.

    Security and audit signals. 2 repos across the fleet with an audit or alert signal, each a security-related failure above: vergil-project/.github#1473 and logical-minds-foundry/.github#413.

    Open security records. 95 open across the fleet, the two above included. Neither signal had a record before this review; both were created in it.

    Decisions¶

    Operational discipline comes before development. Monday 2026-11-23 starts by fixing the four red repos, before any new development:

    1. vergil-project/.github#1473 first, since the fleet's base images are not being rebuilt.
    2. logical-minds-foundry/.github#413.
    3. logical-minds-foundry/mq-resiliency-lab-for-linux#1738 and logical-minds-foundry/mq-resiliency-observability#72, the shared docs-build problem.
    4. mnemosys-project/melete#265.

    Every failure already has an issue; what each lacked was an owner and a day: each is taken on Monday, in this order.

    Follow-ups¶

    • Recorded a security finding: vergil-project/.github#1473.
    • Recorded a security finding: logical-minds-foundry/.github#413.

    Kaizen¶

    • Show how long a failure has been red. Each check compares a run only with the one before it, so a failure red for ten nights looks the same as one red since yesterday. The failed-runs and automation-PR checks should count consecutive red nights.
    • Mechanize the failed-runs check. It ran the same per-repo run list across 33 repos, then per-run and per-job log reads; a run with many jobs cannot return its failed logs in one call. It is the next candidate for a vrg-* tool (history, vergil-project/.github#1317).
    • The user identity cannot see what a security record needs. It cannot read Dependabot alerts or a run's artifacts, so one record was created without naming the package. The review needs a sanctioned way to read them.
    • Nightly sync PRs that close and reopen hide their real age; the checks should report the age of the failure, not of the PR.
